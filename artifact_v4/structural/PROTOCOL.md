# Corrected executable discovery and prospective response evaluation

Revision dated 14 November 2026, after the complete exposed v2 campaign. This is a new experiment, not a retroactive replacement. Preserve P0, v2 and manuscript v7 as historical releases. Its motivation is the documented semantic audit, not selection of seeds or generator constants for favorable test costs.

## Corrections fixed before new main outcomes
1. Canonicalize the trace-language identity seq(loop(body, redo), redo) to loop(seq(body, redo), tau), so a next-activity decision is evaluated after its common visible continuation. Reject remaining unguarded choices with overlapping first-visible labels instead of silently assigning indistinguishable branches. This correction was established by an analytic 2000-case counterexample, not a v2 policy-cost comparison.
2. Enforce explicit binary class/process guards in fitted-model execution as in generator execution. In an analytic common-prefix XOR example the old runtime violated 999 of 2000 guards; the corrected runtime violates none.
3. Automatically select structure from standard IM and loop-first, attribute-guarded IM. The latter uses the existing PM4Py StrictTauLoop fallback before permissive concurrency; it does not patch the installed library. Infer a binary attribute guard only when both values have at least 10 training cases, each value has a constant per-case activity set, and those sets differ. Try observed process then complexity attributes, recursively. No true structure or test outcome is passed to discovery. Among executable candidates with 100% training traces fitting under optimal alignments, choose greatest training precision, then fewer transitions, then the guarded candidate. Factor a common visible prefix out of the inferred guarded branches. Use optimal alignment fitness to avoid false rejection from greedy token replay on duplicate labels; record token replay fitness separately. The admissibility field is percentage_of_fitting_traces = 100, since the library global log_fitness also counts small silent-transition costs and can be below 1 even for perfectly fitting traces. Save every candidate, all guards and the selection. Fitness/precision of PNML describe the control-flow projection; guards remain in executable JSON.

The learned duration/return families, regularization, feature contract, predictive selector thresholds, candidate actions, costs, alarm thresholds, truth generator and calibration settings are unchanged. A 92-run paired audit verifies exact generator trajectories, lifecycle records, completion data and trigger equality before and after the runtime correction for all six processes, four worlds and every action type. Standard IM with the corrected runtime is retained as a structural ablation, separately from the archived uncorrected v2 implementation.

## Fresh independent evaluation
Use all P1-P6 and fixed/service/routing/combined worlds, 12 independent datasets per cell: 288 fits. Original calibration specifications and their hashes are retained unchanged. New main base seed is 1900000000000 + process*1000000000 + world*100000000 + fit*1000000. Technical pilot uses 1800000000000 with disjoint streams and is excluded. Training, validation, planning, and test offsets, arrival horizon, scoring horizon, 48 main test episodes per fit, common random numbers and saved policy catalogue match the reference protocol. No fit is omitted for decision quality. Record pre-crisis violations and executable discovery failures; do not replace failed datasets.

For every independent dataset fit behavior once; compare supplied structure, automatically selected structure and executable standard-IM structure. All three use identical fitted behavior and planning conditions. Compare no action, static, predictive selection, retained load, feedback-strength heuristic, every fixed action/threshold, finite-catalogue known-generator planner, service/routing component ablations and per-return ablations. Oracle uses planning scenarios, never realized future test arrivals. The selected policies and source hashes are sealed before test generation. Preserve P2 mix65 and P3 efficacy30/70 diagnostic tests with unchanged policies. Execute routing fits across all structures first, then the other worlds; this is an execution order, not an early stopping rule.

## Confirmatory hypotheses and analysis
Two primary contrasts are specified for routing feedback and the entire six-process design:
H1: retained-load planning with automatically selected structure has lower mean no-action-normalized test cost than predictive component selection with that same structure.
H2: retained-load planning with automatically selected structure has lower mean no-action-normalized cost than retained-load planning with standard-IM structure, using the same corrected runtime and fitted behavior.

Within each process, average each policy's 48 trajectories for each of 12 independent fitted datasets, divide by that fit's no-action cost, and take the paired method difference. Average the six process means with weight 1/6. Estimate variance from independent fit differences within each process, with Satterthwaite degrees of freedom. Use two-sided 97.5% confidence intervals for each of the two primary contrasts (Bonferroni family alpha 0.05); a benefit is established only when the upper bound is below zero. All six cells must be present with all 12 fit pairs and valid pre-crisis calibration for an unqualified primary claim. Report pipeline failure coverage separately; never silently condition away failures.

Per-process routing contrasts are secondary, with 95% intervals and an additional six-comparison Bonferroni interval. Other worlds, known structure, oracle regret, simple-heuristic comparisons, selector thresholds, effect uncertainty, triggers, severe events, structural metrics and subgroup outcomes are diagnostic. Do not call a retrospective policy minimum an executable oracle. Report material contrary findings and do not treat the six constructed processes as a representative random sample of all workflows. Primary hypotheses differ from the old per-process known-structure v2 family; do not relabel those exposed results as successful confirmation.
